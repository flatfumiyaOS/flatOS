# 見積書作成

現場監督・施工管理の業務で使う、案件ごとの御見積書・御見積内訳書をGoogleスプレッドシートのテンプレートに入力するスキル。工程表作成とは違い、新規ファイルをスクリプトで生成するのではなく、既存のテンプレート（「御見積書」「御見積内訳書」の2シート）のセルを直接編集する。

## 明細の作り方には2つの入力パターンがある

依頼された内容から、どちらのパターンかをまず判断する。迷ったら自己判断せず本人に確認する。

- **パターンA: 図面から自動で明細を組み立てる（従来の方法）**
  図面・仕様書を読み込み、AIが工種・数量などを判断して明細を組み立てる。実際の仕入額が
  分からないため、単価（E列）は空欄のままにする。
- **パターンB: 業者（外注先）から受け取った見積書の明細をそのままコピーする**
  弊社は業者見積の金額をそのまま計上し、利益はすべて【諸経費】側で計上する方式のため、
  このパターンではパターンAと異なり、**単価（E列）・金額（F列）も業者見積書の記載通りに
  入力する**。
  - 摘要・数量・単位・単価は業者見積書の記載をそのまま転記する（数値を変更・計算し直さない）。
  - 金額（F列）は他のパターンと同様「数量×単価」の数式にするのが基本だが、業者見積書の
    その行の金額が数量×単価と一致しない場合は、数式にせず業者見積書記載の金額をそのまま
    数値で入力し、本人にその旨を伝える。
  - 業者見積書に工種の区切りが無い、または弊社のテンプレートと異なる分類になっている
    場合も、パターンAと同じ【〜工事】見出しのルール（下記「明細の組み立て方」参照）に
    従って、内容を見て工種ごとに分類・整理して見出しを付け直す（業者見積書側の項目分けを
    そのまま踏襲する必要はない）。
  - 【諸経費】は、明細に業者見積書由来の内容が無くても、パターンAと同じくデフォルトの
    見出し・小計行・出精値引き行を用意しておく（中身は空欄のまま担当者の入力に委ねる。
    下記ルール5参照）。

## 前提として毎回やること

1. 案件フォルダ内にある該当案件の図面・改修内容（PDFや画像など）、またはパターンBの
   場合は業者から受け取った見積書（PDFや画像、チャットに貼られたテキストなど）を読み込み、
   スコープ（どの工種の工事が発生するか）を把握する。
2. 編集を始める前に `read_sheet_range` で実際のテンプレートの記載例（工事項目名の書き方、小計・出精値引きの数式など）を確認する。体裁が変更されている可能性があるため、記憶に頼らず都度確認する。ただし、これは書き方の見本を1〜2個の工事項目分だけ把握できれば十分なので、**先頭付近の40〜60行程度を読めば足りる**。テンプレートには別案件の明細がそのまま大量に残っていることがあるが、それを全件読み込んで内容を理解する必要はない（後述のとおり、不要な行は中身を確認せずまとめて削除してよい）。
3. CLAUDE.mdの方針どおり、ファイルの削除は行わない。
4. 単価（E列）は、パターンA（図面から自動生成）では担当者が後から入力する欄なので絶対に
   埋めず空欄のままにする。パターンB（業者見積書のコピー）では逆に、業者見積書に書かれた
   単価をそのまま入力する。
5. 【諸経費】の中身（既に入っている金額・項目そのもの）は担当者が編集するため、絶対に
   変更しない。ただし【諸経費】の見出し・小計行・出精値引き行という「枠」自体は、
   テンプレートに存在しない場合パターンA・B問わず用意する（中身は空欄のまま）。
   【弊社直接施工等】も同様に、テンプレートに存在しない場合は見出し・小計行を必ず用意
   する（こちらは現場調査費・現場管理費をAIが計上してよい。中身が担当者専用という
   意味ではない）。この2項目は、他の工種と違って該当する工事の有無にかかわらず常に
   明細に含める。
6. 見積番号（No:）欄は編集対象外。触らない。

## 明細の組み立て方（過去の見積書10件の実例から学んだパターン）

- 明細は工種ごとに【仮設工事】【解体工事】【軽鉄・ボード工事】【造作工事】【塗装工事】【内装仕上げ工事】【ガラス工事】【タイル・左官工事】【照明器具】【電気工事】【床暖房工事】【空調設備工事】【換気設備工事】【給排水設備工事】【ガス設備工事】【住宅設備機器】【什器工事】【サイン工事】【備品・雑工事】のように【】見出しで区切る。
- **その工事で発生しない工種の見出しは書かない（丸ごと省略する）。** 「別途工事」のような0円のプレースホルダー行を残す必要はない。案件の図面・スコープに合わせて、必要な工種だけを過不足なく入れる。
  **ただし【弊社直接施工等】と【諸経費】の2つは例外で、案件の内容によらず常に置いておく項目とする（省略しない）。**
- 工種の中をさらに〈建具工事〉〈木工造作工事〉〈金物造作工事〉のようにサブ区分することがある（規模が大きい案件で使う）。
- 各明細行は「摘要（品名・仕様など）／数量／単位／単価／金額」で構成する。
  - 単位は「式」「本」「枚」「台」「箇所」「㎡」「ｍ」「日」「人工」などを内容に応じて使い分ける。
  - 材料費は「品番・メーカー名／定価¥○○」のように仕入先の定価を摘要欄に併記することが多い（パターンAでは単価自体は担当者が後で入力するので空欄のまま。パターンBでは業者見積書の単価をそのまま入力する）。
- 各工種の末尾には、実態に応じて運搬搬入費・残材発生材処理費・交通費諸経費などの行を入れる（毎回すべて入れるわけではない）。
- 【弊社直接施工等】には現場調査費、現場管理費（日数×単価/日）を計上する。**この項目は【諸経費】と同様、案件の内容にかかわらず常に明細に含める（他の工種と違い、該当する工事が無いという理由で省略しない）。**
- 【諸経費】（他社施工分手数料・出張費・交通費・法定福利費・一般管理費・出精値引きなど）は担当者が編集する欄なので、AIは中身を作成・変更しない。**「出精値引き」の行も【諸経費】の一部として、そこに元から含まれている。** テンプレートに既に【諸経費】と出精値引きの行が存在する場合、AIが書いた明細の末尾に別途「出精値引き」の行を新しく作らない（二重になってしまう）。もし読み込んだ範囲に【諸経費】が見当たらない場合のみ、担当者に確認してから対応する。

## スプレッドシート編集の技術的ルール

見積書スプレッドシートを編集するとき（パターンA・Bいずれの場合も）は、次のルールを必ず守る。

【共通のルール】
- 以下のセルは絶対に変更しない: A12, A14〜24, B16〜20, F5, E10, F10, E18〜27, A30〜F30
- 見積書は「御見積書」（工事項目ごとの合計金額のみを記載）と「御見積内訳書」（工事項目ごとの明細）の2つのシートをセットで作成・編集する。
- フォントや文字サイズは変更しない（セルの値だけを書き換え、書式は変更しないこと）。

【御見積内訳書のルール】
- 明細は32行目から書き始める。32行目に工事項目名を【】で囲んで記載し（例に倣う）、その下の行（33行目〜）から明細（品名・数量・単位・単価・金額など）を書き出す。
- 発生しない工種の見出しは書かない（上記のとおり省略する）。
- 金額列（F列、33行目以降）は「数量（C列）× 単価（E列）」の数式にするのが基本（パターンBで
  業者見積書の金額と数式の結果が一致しない場合のみ、上記の通り数値をそのまま入力する）。
- 単価（E列）は、パターンAでは担当者が後から入力するため空欄のままにする。パターンBでは
  業者見積書に書かれた単価をそのまま入力する。
- 各工事項目の明細の最後の行には、小計を `=SUM(...)` の数式で入力する（例に倣う）。数式を必ず使用し、手入力の数値を入れない。
- ある工事項目の小計行と、次の工事項目の【】見出し行の間は1行空ける。
- 【諸経費】の明細の中身は担当者が編集するため、絶対に変更しない。
- 諸経費の小計行の下には、例に倣って「出精値引き」の行を用意する。出精値引きの単価も担当者が編集するため、空欄のままにする。
- 「出精値引き」より下の行は変更しない。
- 明細の行数は実際の項目数に応じて過不足なく調整する（テンプレートの余分な行は削除する）。
- 行の高さは、明細部分（32行目以降）は標準28px、表紙部分（1〜31行目）は21pxで統一されている。**この2つの区画の違いはそのままにする（触らない）が、明細部分の中で高さがバラついている行があれば、`set_sheet_row_height`で28pxに揃える。** ただし、その行の文章が実際に2行に折り返すほど長い場合は、その行だけ56px（28pxの倍）にしてよい。

【御見積書のルール】
- こちらも明細は32行目から書き始める。
- 「御見積内訳書」に記載した工事項目名を、【】を外してそのまま上から順に記載する。
  **【諸経費】も他の工種と同じく1行として必ず含める**（中身を作成・変更しないのは
  「御見積内訳書」側の諸経費の明細内容についてのルールであり、御見積書に諸経費の
  行自体を書かない、という意味ではない）。この行を忘れると合計金額が大きくずれる。
- 各工事項目の金額は手入力せず、「御見積内訳書」の対応する小計セルを参照する数式（例: `=御見積内訳書!F40`）にする。
- 諸経費の下の行には、例に倣って「出精値引き」の行を入れる。単価は担当者が編集するため空欄のままにする。
- 「出精値引き」より下の行は変更しない。
- こちらは明細が少なくても行を削除しない。**49行目以降が固定**（出精値引き=49、小計=50、税率別内訳=51、合計=52、備考=54、備考の注記=55〜57）。工事項目とその下の行（32〜48行目）に空白行ができても構わないが、罫線（セルの枠線）は変更しない。
- 御見積内訳書と同様、最下部に「備考」欄がある（54行目「備考」、55〜57行目に注記3行）。この内容は担当者が編集する欄なので、AIは変更しない。

## 手順

1. 図面・ヒアリング内容から工事スコープを整理し、発生する工種のリストを組み立てる（発生しない工種は最初から入れない）。
2. `read_sheet_range` でテンプレートの記載例（工事項目・小計・出精値引きの書き方など）を確認する。
3. 「御見積内訳書」から明細を書き込み、次に「御見積書」側で工事項目名と小計参照の数式を反映する。
4. 修正依頼（工種の削除・追加、明細の変更など）が来たら、該当箇所だけを差分で編集する。全部作り直さない。

## 大きな既存内容の消し方（重要・トークン消費対策）

テンプレートには前の案件の明細がそのまま残っていることがある（過去の大規模案件の例だと、明細だけで200行を超えることもある）。これを新しい案件の内容に置き換えるときは、次の順番を必ず守ること。

1. まず `read_sheet_range` は書き方の見本を掴むための先頭40〜60行程度だけにとどめる（上記のとおり）。既存の明細が何行あるかは、シートの末尾付近（例: 300行目あたり）を軽く確認する程度で十分で、**既存の内容を1件ずつ読んで理解する必要はない**。
2. 既存の明細行は、中身を読まずに `delete_sheet_rows` で範囲ごとまとめて削除する（例: 32行目〜299行目を一括削除、など）。中身を1件ずつ空文字で上書きするような`write_sheet_range`は使わない。
3. 削除して空になったところに、新しい案件の明細を工種（【】見出し）ごとに分けて`write_sheet_range`で書き込む（1回のツール呼び出しを小さく保つ）。

この順番を守らず、既存の大量の明細を全部読み込んでから書き換えようとすると、一度のやり取りで扱う情報量が膨大になり、応答が長さの上限に達して途中で打ち切られ、処理が完了しないことがある。

## 明細を書き終えたら必ず行うこと（仕上げ）

明細（御見積内訳書）を一式書き終えたら、そこで作業を終わらせず、必ず次の仕上げを行う。

1. 最後に書き込んだ工事項目の小計行のすぐ下から、【諸経費】の直前（空行を1行残す）までの間に、使わなかった空白行が残っていないか確認する。残っていれば`delete_sheet_rows`でまとめて削除し、【諸経費】が明細のすぐ下に詰まった状態にする。書いた内容と【諸経費】の間に大きな空白ができたままにしない。
2. 明細部分（32行目〜）の行の高さが28pxで揃っているか確認する（上記「行の高さ」のルール通り）。テンプレートから引き継いだ高さが混ざっていないか、特に文章を短く書き直した行に注意する。
